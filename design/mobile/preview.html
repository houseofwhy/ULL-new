Design proposal

The phone gets the same vocabulary as the desk

The desktop pages now speak one language: an eyebrow for every section heading, one status pill on the list's own colour scale, meters for the two progress numbers, stat cards for the records, a definition list for the facts, chips for tags and creators. The mobile tree speaks none of it. It still writes “Status: Decoration 80% done” and “WR From 0: None” as sentences, under headings in a purple that appears nowhere else, and it is missing a dozen things the desktop gained along the way.

So these templates add almost no CSS. Everything a phone shares with the desktop comes from css/ull-v2.css unchanged; the new file is small and holds only what genuinely differs at 390px — one column, a detail that expands under its row instead of sitting beside it, controls within thumb reach, and a type scale one step down.

Constraint
Every feature the desktop has, nothing the desktop doesn't.
Reused
css/ull-v2.css as-is: pill, meter, stat, card, chip, rank, eyebrow, button, empty state.
New
One stylesheet for the phone: rows, the expanded detail, the tab bar and the sheet.
Not covered
Information, which the desktop has not been reworked for yet either.

Home

/mobile/home
js/pages/mobile/MobileHome.js · css/pages/mobile.css
What is wrong now

A purple centred headline, four full-width stacked buttons and an "Other Pages ▼" accordion fill the whole first screen without showing a single level. Below that, Recent Changes is a flat run of em-dashes inside a bordered scroll box and the editors are one undifferentiated list. The desktop home gained a count strip, the top five levels, a dated timeline and editors grouped by role; none of it crossed over.

What the template changes

The same four blocks as the desktop, stacked: hero, the count strip, the top five levels as tap rows with their status pill, the timeline with its coloured dots, the editors grouped. The four navigation buttons go: those destinations are the tab bar at the bottom of every page now. Under the hero sits the desktop's credentials bar — how much the list holds, how long it has been running — rather than five count chips inside it: home is the only page with a hero this size, so it is the only one that gets the room. The desktop's third item, who uses it, does not fit a phone line and is dropped.

Level list

/mobile/all · /mobile/main · /mobile/future
js/pages/mobile/MobileList.js · css/pages/mobile.css
What is wrong now

Tapping a row opens the detail the desktop panel used to look like before it was rebuilt — "#2 in Main List" as dim grey text, a three-row author table, "Status: Decoration 80% done" and "WR From 0: None" as sentences, then the video and three bare stats. There is no status pill, no progress meter, no record card, no rank chip, no creators chips, and no way to reach the level's own page or copy a link to it, all of which the desktop panel now has.

What the template changes

The expanded row shows four short lines — where the level stands, how far it has got, and the best two records — then a button to the level's own page, which is the full record. Unfolding everything here pushes the next level most of a screen down, so the video, creators, tags, ID and length stay one tap away rather than in the way. The row itself keeps its rank, thumbnail and name, and gains the status pill the desktop rows carry.

Upcoming Levels

/mobile/upcoming
js/pages/mobile/MobileUpcoming.js
What is wrong now

The page is ordered by how far anyone has got into each level, and shows that only as "WR: 99% · Run: 24-100" in the row's second line — the same omission the desktop page had before it was fixed. Its expanded detail is a cut-down of the list detail, so it inherits every problem that one has.

What the template changes

The ranking metric becomes the row's visual: the progress bar the ordering is built from, with the reading at the end of the row where the eye runs down it. The expanded row opens on that same figure at full size and the two records behind it, then a button to the level's own page — the same short summary the list pages use.

Leaderboard

/mobile/leaderboard
js/pages/mobile/MobileLeaderboard.js
What is wrong now

Every player is an identical row reading "Score: 11888.473" in the same weight as their name, with nothing marking first place from two-hundredth. Tapping one opens a records list built from about a dozen inline style attributes, with no total, no type pills and no alignment between the score column and the names. The desktop page has a podium, a display total and a pill per record type.

What the template changes

The podium comes over, sized for a phone. Rows put the score at the right in tabular figures so the column reads down — and since the row already states the player's total, the expanded panel does not repeat it as a display figure; it goes straight to the records. Each record is one line: what it was worth, which level, and what it was.

Pending List

/mobile/pending
js/pages/mobile/MobilePending.js
What is wrong now

Four cards under a centred purple headline, each row an icon and a name. The placement a level is waiting for — the one fact the page exists to state — is encoded only in which of six SVG icons is drawn, so "Top 10" and "Top 75" look the same at a glance. There are no counts and no colour separating a placement from a removal; the desktop page gained all three.

What the template changes

The desktop's four lanes, stacked one per row on a phone: the same tint per lane, the same count beside each heading, and the placement spelled out as a chip beside every name. The hero's four counts are buttons that jump to the lane they count, so a long queue is one tap deep rather than a scroll.

Events

/mobile/events
js/pages/mobile/MobileEvents.js
What is wrong now

The three features are drawn three different ways and in the wrong order — Level of the Month first, Level of the Day last, opposite to the desktop. Each is a flat thumbnail box with a name, a rank and an ID chip; none carries the status pill, the tags or the details the desktop features gained, and the record rows put their label on the right where it reads as a caption for the wrong line.

What the template changes

One feature block at one size, in the desktop's order: Level of the Day first with its status pill, tags and details, then Level of the Month and Closest to Verification. The thumbnail moves behind the title as it does everywhere else, and the label and its date sit together on one line.

Filters & settings

any list page
js/pages/Mobile.js · css/pages/mobile.css
What is wrong now

Filters and settings open as a centred popup with its own scroll box and a hand-drawn "⌄" hint underneath, so the Apply and Reset buttons land in the middle of the screen, away from the thumb. The filter rows are check-boxes stacked one per line, which needs a long scroll to reach the tag you want. The theme toggle labels the buttons Dark and Light while the class that drives it is inverted, which is why the desktop settings and this one disagree about which is which.

What the template changes

A bottom sheet: the actions sit at the bottom edge where the thumb already is, and the filters become a wrapped chip field so most of the list is visible without scrolling. The two numeric filters keep their own row. Settings uses the same sheet, with the same four toggles the current build has and no more.

Level page

/level/<slug> on a phone
js/pages/LevelPage.js · css/pages/level-page.css
What is wrong now

This is the URL every shared link and search result points at, and it is the one route that never redirects to /mobile. The page itself already stacks correctly on a phone, but it arrives wearing the desktop chrome: the floating sidebar toggle sits over the hero, and there is no way back into the mobile tree once you land. A visitor who taps a shared link is stranded outside the app.

What the template changes

The page keeps its own layout untouched — it works. It just gets the mobile shell around it: the top bar and the tab bar, with the breadcrumb as the way back into All Levels. Nothing about the content changes.
