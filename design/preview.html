Design proposal

Bring the rest of the site up to the level page

/level/<slug> already contains the answer. It introduces a level with its own blurred thumbnail, says where it stands with one status pill on a colour scale shared with the list, draws its two progress numbers as meters, and puts its facts in a definition list — in one stylesheet, with no inline styles. Every other page states the same things in prose, in a different size, in a colour picked for that page alone.

These six templates lift that vocabulary into a shared layer, design/ull-v2.css, and rebuild each page out of it. No new data: every value shown already exists in the level JSON or is derived from it the way the list already derives it, and no page gains a written description of a level.

Building the templates turned up a live bug worth fixing either way: in css/pages/level-page.css, .level-page a { color: inherit } scores higher than .lvl-link, so on the light theme the filled “Showcase video” button on every level page draws black text on its #3e00f9 fill instead of white. The shared layer scopes each component one level deeper so the cascade resolves the way it reads.

Constraint
No new fields, and no per-level prose anywhere.
Untouched
The page structure of All Levels, Main List and Future List. Only their level container is rebuilt.
Deleted
63 inline style attributes across these six pages — 109 counting the three list pages that duplicate each other — and .upcoming-hero, which repeats .page-hero rule for rule.
Not covered
Information, which has its own deck of four competing templates. Admin and the generator are staff tools and left alone.

Home

/
js/pages/Home.js · css/pages/home.css
What is wrong now

The landing page of a level list shows no levels. Above the fold there is a 60-word paragraph and three buttons all styled .home-btn--primary, so nothing is primary; below it, two cards, one of which is a staff roster. A first-time visitor learns what the list is but never sees what is on it, and a returning visitor has to click through to find out what moved.

What the template changes

Keep the hero copy and the two existing cards, and put the list itself on the page between them. Under the hero, three things about the list — how much it holds, how long it has been running and who uses it — as a row of icons and lines; then the top five rows of All Levels rendered with the same row, status pill and rank vocabulary the level page uses. One filled CTA, the rest ghost. Recent Changes becomes a dated timeline instead of a scroll box of dashes.

Level container

/list · /listmain · /listfuture
js/pages/List.js · ListMain.js · ListFuture.js · css/pages/list.css
What is wrong now

The right-hand panel is the only part of these three pages you asked to keep open, and it is the part that has drifted furthest. It renders four near-identical v-if branches to print "World Record - From 0: None", a "Status: Decoration being made - 80% done" sentence, cross-list ranks as dimmed grey text, and a three-item .stats row spread with justify-content: space-evenly so ID, Length and Last Update drift apart on a wide panel. Roughly forty style="" attributes live in the template. Meanwhile /level/<slug> shows the same data, better, right next to it.

What the template changes

Rebuild the panel out of the level page's own components — thumbnail hero, status pill, rank chips, meters, world-record stats, a facts list — so the panel and the standalone page are the same design at two sizes. The page grid, the hero and the list column are untouched; the list rows only gain the shared row rhythm. Every value shown is one the panel already had.

Upcoming Levels

/upcoming
js/pages/UpcomingLevels.js · css/pages/list-hero.css
What is wrong now

This page ranks levels by how far anyone has got into them, and then never shows that number as anything but a "WR: 20% | Run: 72-100%" caption. Its hero is .page-hero repeated rule for rule under a second name, .upcoming-hero — the two blocks differ only in the class prefix — so the same component is maintained twice. Its detail panel is a cut-down of the list panel: name, dim grey cross-list ranks, best progress, best run, video — and nothing else.

What the template changes

The ranking metric becomes the visual: each row carries the progress bar the ordering is built from, so the list reads as a race rather than an arbitrary order. The panel leads with that same figure at full size, then reuses the level container components below it. The duplicate hero collapses into the shared .u-phero.

Leaderboard

/leaderboard
js/pages/Leaderboard.js · css/pages/leaderboard.css
What is wrong now

The player panel is one <h1>, a "Total Score: 12.408" sentence and a borrowed table, all styled by about twenty-five inline style attributes written into the template. Nothing distinguishes #1 from #240. The score column is the whole point of the page and it is set in the same weight and colour as the name beside it. css/pages/leaderboard.css still styles a .board / .player markup the page stopped rendering.

What the template changes

Give the left column a podium for the top three and the shared row rhythm below it, with the score right-aligned and tabular so the columns line up. Turn the right panel into a profile: the total as a display figure, then records as rows carrying a score chip, the level rank, and a type pill. Per-record scores are already computed in js/leaderboard.js.

Pending List

/pending
js/pages/ListPending.js · css/pages/list-pending.css
What is wrong now

The heading is set in #c084fc, a lilac that appears nowhere else on the site and is not derived from the theme, so the page looks like it belongs to a different product. The four groups are laid out as one tall card beside a stack of three, which makes "Pending Placements" read as more important than the others by accident of column width. Cards lift on hover with transform: scale(1.006), nudging their neighbours. A row shows an icon and a name, so the placement the level is pending for — the one fact the page exists to communicate — is encoded only in which of six SVG icons is drawn.

What the template changes

Four equal-width lanes in two independent stacks, coloured by what each means rather than by decoration, so a short lane never holds the one beneath it down to the bottom of the tall lane beside it. The pending placement is spelled out as a chip beside the name, with the icon kept as the quick scan. A count strip up top so the page answers "how much is in the queue" before you read any of it. Theme-derived colour throughout; no hover scaling.

Events

/events
js/pages/Events.js · css/pages/home.css
What is wrong now

Events borrows .home-card, .info-hero and .info-content from two other pages, so changing the home page changes this one. Its three features are the same kind of thing — a level being pointed at — yet each is drawn differently: Level of the Day gets a two-column card with an "Additional Information" sub-heading, Level of the Month gets a compact header, and the closest-to-verification card gets a third shape. The level thumbnail sits in a 4.4rem box while the level page next door builds a whole hero out of the same image.

What the template changes

Three features, one component. Level of the Day leads at full width with the level page's thumbnail hero, its status pill and its facts; the other two are the same block at half width. What differs between them is the label and the date, which is exactly what differs about them.
