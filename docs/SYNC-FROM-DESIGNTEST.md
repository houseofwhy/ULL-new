# Bringing design work from `ULL-designtest` back into `ULL-new`

You are about to move design changes from **`Upcoming-Levels-List/ULL-designtest`**
into **`houseofwhy/ULL-new`**, which is the live site.

**Do not follow [`MOVE-TO-MAIN-REPO.md`](MOVE-TO-MAIN-REPO.md).** That document
describes a one-time migration that replaced ULL-new's whole tree with
designtest's, back when ULL-new was the stale copy. Running it today would take
the live site down a level — see the hazards below. It is kept for history.

The relationship is now inverted: **ULL-new is the source of truth**, designtest
is a mirror of it that gets design work done on top. So the job is not "replace
the tree", it is "bring across the source files that changed, then regenerate".

---

## Read this first: four ways to break the live site

designtest is deliberately **not** an exact copy of ULL-new. Four differences
will damage the live site if you copy the tree wholesale.

### 1. designtest has no `.github/workflows/`

It was removed on purpose when designtest was resynced — an hourly bot
committing to a test repo is noise. ULL-new's copy of
`.github/workflows/refresh-content.yml` is what keeps the crawler-visible pages
in step with the live list. **A wholesale copy deletes it**, and nobody notices
until the static pages are weeks stale.

> Never copy the absence of a file. Only bring paths you have decided to bring.

### 2. designtest's `robots.txt` says `Disallow: /`

designtest has its own Cloudflare Pages deploy, so its `robots.txt` is a blanket
disallow to keep the test build out of search results. **Shipping that file
de-indexes the live site.** `robots.txt` is the one file that is expected to
differ between the two repos. Never bring it across.

### 3. designtest's generated content is frozen; ULL-new's is live

Because designtest has no refresh workflow, everything the bot regenerates is
frozen at whatever moment designtest was last resynced. ULL-new's copies are
refreshed hourly. Copying designtest's versions **rolls the crawler-visible site
back** by however long it has been.

### 4. `data/_level-registry.json` is append-only memory

It records every `/level/<slug>` URL the site has ever published, and
`scripts/seo/registry.mjs` uses it to decide what each URL serves — a live page,
a 301 to a renamed slug, or a 180-day grace period for a removed level. Rolling
it back to an older copy **forgets slugs published since**, which breaks
redirects that search engines already follow and can let a slug be silently
reused for a different level. Treat it as a database, not a build artifact.

## What is generated and what is hand-maintained

The authoritative list of generated surfaces is the `git add -A` block in
`.github/workflows/refresh-content.yml` — if that file and this table ever
disagree, the workflow is right.

| Never bring from designtest | Why |
|---|---|
| `robots.txt` | designtest's is `Disallow: /` |
| `.github/**` | designtest has none |
| `css/bundle.css` | generated by `scripts/build-css.mjs` |
| `js/seo-meta.js` | generated by `scripts/build-seo.mjs` |
| `sitemap.xml`, `llms.txt` | generated by `scripts/build-seo.mjs` |
| `_redirects` | its marked block is generated (the SPA rule is not — regenerate, don't hand-edit) |
| `data/_seo-snapshot.json` | generated by `scripts/fetch-data.mjs` |
| `data/_level-registry.json` | append-only; see hazard 4 |
| `level/`, `list/`, `listmain/`, `listfuture/`, `upcoming/`, `pending/`, `leaderboard/`, `events/`, `information/` | pre-rendered pages |

| Bring from designtest | Notes |
|---|---|
| `js/**` | except `js/seo-meta.js` |
| `css/**` | except `css/bundle.css` |
| `scripts/**` | including `scripts/seo/content.mjs`, which holds the page copy |
| `worker/**` | deploying it is a separate manual step — see `database.md` §2 |
| `assets/**`, `index.html`, `*.md`, loose root files | `index.html` is safe to copy: its `seo:head` / `seo:content` regions are rewritten by the build in step 5 |

`index.html` is the one file that is both. Everything outside the `seo:head` and
`seo:content` markers is hand-maintained and is copied verbatim into every
generated page; everything inside is regenerated. Copy it, then rebuild.

## The procedure

### 1. Branch from current `main`

The hourly bot commits to `main`, so start from the newest commit and expect to
rebase before you push.

```bash
git fetch origin main
git checkout -b sync-designtest origin/main
```

### 2. Fetch designtest and see what actually changed

```bash
git remote remove designtest 2>/dev/null
git remote add designtest https://github.com/Upcoming-Levels-List/ULL-designtest.git
git fetch designtest main
git diff --stat origin/main designtest/main
```

Read that diff before doing anything else. If the only differences are
`robots.txt`, `.github/`, and the generated surfaces in the table above, there is
**no design work to bring** — designtest is just drifting behind. Stop here.

### 3. Take only the source paths

```bash
git checkout designtest/main -- js css scripts worker assets index.html
```

Add any other hand-maintained paths the diff showed. Then undo the generated
files that ride along inside those directories:

```bash
git checkout origin/main -- css/bundle.css js/seo-meta.js
```

If designtest **deleted** a source file, `git checkout` will not remove it — check
the diff for deletions and `git rm` them by hand.

### 4. Confirm nothing forbidden came across

```bash
git status --short
```

`robots.txt`, `.github/`, `data/_level-registry.json`, `data/_seo-snapshot.json`,
`sitemap.xml`, `llms.txt`, `_redirects` and the pre-rendered page directories
must **not** appear. If any do, restore them:

```bash
git checkout origin/main -- robots.txt .github data/_level-registry.json
```

### 5. Regenerate

```bash
node scripts/build-css.mjs
node scripts/build-seo.mjs
```

`build-css.mjs` rebuilds `css/bundle.css` from the stylesheet list in
`index.html`, in that exact order — the cascade depends on it. If you added a
stylesheet, add it to the commented `css:start` block in `index.html` first.

`build-seo.mjs` regenerates the pre-rendered pages from the snapshot already
committed in ULL-new. Do **not** run `fetch-data.mjs` as part of this change —
mixing a data refresh into a design PR makes the diff unreviewable, and the
hourly bot will refresh within the hour anyway.

### 6. Run the tests

```bash
node js/registry.test.mjs
node js/util.test.mjs
node js/leaderboard.test.mjs
node js/upcoming.test.mjs

npm i playwright vue@3.2.31 vue-router@4.0.14
node css/mobile-footer.test.mjs
node js/list-ui.test.mjs
node js/pending-ui.test.mjs
node js/seo.test.mjs
node scripts/e2e-test.mjs
```

`js/registry.test.mjs` is the one that catches a damaged slug registry, and
`js/seo.test.mjs` is the one that catches a broken pre-render or a static block
that leaks to visitors. Neither is optional.

If the design work renamed a CSS class or a DOM hook, the Playwright tests will
fail on stale selectors — fix the tests, do not weaken them.

### 7. Check by hand

Design changes are exactly what the tests cover least. Serve the repo root
locally and look at:

- both themes (the settings popup toggles it) — a colour defined only for dark
  is the classic bug;
- a phone-width viewport, and `/level/<slug>`, which is standalone and does not
  redirect to `/mobile`;
- a level in each state: verified, being verified, layout, no creators, no
  video, and a slug that does not exist.

### 8. Open a PR

```bash
git add -A
git commit -m "Bring <what> across from designtest"
git fetch origin main && git rebase origin/main
git push -u origin sync-designtest
```

Rebase immediately before pushing — the bot may have committed while you worked.
Open the PR against `main`; say in the body which designtest commits you brought
and confirm that `robots.txt` and `.github/` were left alone.

---

## Afterwards

Once merged, designtest is behind again. Resync it so the next round of design
work starts from the live tree — that procedure is the mirror of this one and is
recorded in the repository's history; the short version is to replace
designtest's tree with ULL-new's `main`, delete `.github/workflows`, and restore
its `Disallow: /` robots.txt.

## If something is already broken

- **Static pages are weeks stale.** The refresh workflow was probably deleted.
  Check `.github/workflows/refresh-content.yml` exists on `main`, then run it
  manually from the Actions tab.
- **The live site vanished from search.** Check `robots.txt` on `main` for
  `Disallow: /`. Restore it from before the merge and request re-indexing.
- **A level URL 404s that used to work.** `data/_level-registry.json` was rolled
  back. Restore it from a commit before the merge; the registry is append-only,
  so the newer file is always the correct one.
- **Refreshing `/list` 404s but clicking links works.** `_redirects` is missing
  from the repo root. It only takes effect on a Cloudflare Pages deploy, never
  locally.

More detail on all of these is in [`../README.md`](../README.md) (Search & AI
visibility) and [`../database.md`](../database.md).
